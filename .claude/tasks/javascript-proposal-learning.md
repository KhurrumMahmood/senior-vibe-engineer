# JavaScript proposal-artifact cohort learning

## Earned contract

The proposal half of the JavaScript cohort is supported only through the
existing, family-local TypeScript Compiler API runners. Each runner accepts
`.js`, `.jsx`, `.mjs`, and `.cjs`; uses the host's locally installed
`typescript`; and, for JavaScript, requires a named `jsconfig.json` or
`tsconfig.json` with both `allowJs` and `checkJs`. No runner installs tooling,
uses `npx`, assumes a global compiler, or imports a repository-level shared
JavaScript service.

| Skill | Final artifact and evidence | Ready outcome | Honest non-ready outcome |
|---|---|---|---|
| `extract-enum` | `targets.json` + `proposal.md`, consumed from the checked-JS implicit-state JSONL and manifest | One finite JSDoc-attested carrier with first-party literal operations becomes a runtime value-object proposal | Missing manifest/tool/config, partial detector evidence, untyped carrier, or open-only evidence exits 2 before output |
| `propose-boundary` | compiler-resolved `inspection.json` + `proposal.md` | Public API, caller impact, private reaches, and compatibility/barrel plan for a real multi-domain partition | Cohesive target defers; unresolved/ambiguous graph defers; selected files outside config are `partial`; bad config/tool/syntax/symlink exits 2 |
| `propose-folder-reorganization` | exact move/import `inspection.json` + `proposal.md` | Three or more human-confirmed prefix siblings with every static direct/alias/barrel/literal-require rewrite | Cohesive, scratch, excluded, below-threshold defer; unlisted selected files are `partial`; unresolved import blocks; bad config/tool/syntax/symlink exits 2 |
| `unify-shadows` | cited `proposal.md`, `evidence.json`, `scope.json` | One `confirmed`, function-level JavaScript finding with current `.js`/`.jsx`/`.mjs`/`.cjs` spans and matrix rows | Partial/uncertain/malformed/wrong-language input exits 2 before synthesis; `keep_separate_document_why` is a successful no-merge proposal |

## Verification retained in the cohort

`tests/test_javascript_proposal_cohort.py` creates a checked mixed JS/TS host,
runs native `npm run check-js` and `npm test`, and executes copied versions of
all four selected skills. It proves four-suffix final artifacts, source hashes,
the exact JavaScript folder move plan through a disposable host typecheck, and
the refusal boundaries for missing config, partial config, malformed input,
symlinks, open strings, and partial semantic findings. Existing TypeScript
outcome suites remain the regression contract.

## Transferable learning

- A language extension is not support. The proposal must reach the same final
  review artifact as the established family and state whether its evidence is
  complete, partial, deferred, unsupported, or failed.
- Reuse the narrowest proven host-local engine. JavaScript inherited individual
  skill-local Compiler API paths because the TypeScript variants already needed
  resolution or checked source facts; this did not justify a shared AST or
  execution platform.
- Treat configuration coverage as a fact. A project can be mixed JS/TS while a
  named config covers only part of the JavaScript target. Emit `partial` and
  list uncovered files rather than quietly analysing them through an ad-hoc
  program root.
- Preserve module syntax requirements in executable proposals. JavaScript ESM
  relative imports and `paths` aliases retain their file extensions after a
  move; TypeScript's extension-elision convention is not portable to checked
  JavaScript. Literal CommonJS `require(...)` is a static edge only when its
  argument is a string literal; dynamic require remains unresolved.
- Proposal consumers need evidence provenance, not only a language label.
  Closed-state extraction requires the detector's checked-JS manifest and
  finite JSDoc authority. Semantic unification requires a confirmed structured
  finding and capability matrix. Neither is allowed to reconstruct authority
  from bare strings or a prose report.
- A deferral can be the complete artifact. A cohesive graph and intentional
  keep-separate shadow are successful review outcomes because they prevent a
  speculative refactor.
- Copied-skill tests should prove closure at the executable boundary. Copy the
  selected skill directory, run it from a separate location against a host with
  its own tool dependency, and assert the copied runner has no checkout path or
  shared-runtime import.

## Non-transferable learning and limits

- JavaScript's JSDoc authority is meaningful here only because the upstream
  checked-state detector already distinguishes finite authority from open
  strings. A Go, Rust, Java, or other language port must establish its own
  authority predicate and cannot treat comments or type names as equivalent.
- The TypeScript Compiler API's resolution behavior, JSX parser mode, and
  `allowJs`/`checkJs` coverage rules are TypeScript-host details. They are not a
  model for a universal language adapter. Go should start from `go list` plus
  `go/types`/its native analyzer; Rust should start from Cargo/rust-analyzer or
  compiler facts; both need their own failure and partial-coverage vocabulary.
- JavaScript's ESM extension retention and CommonJS literal `require` handling
  do not carry to languages with package imports, build tags, macros,
  generated-code conventions, or compile-time conditional imports. Do not copy
  the move-specifier rewriting algorithm without a native native-check proof.
- The four proposal scripts have intentionally different input contracts:
  detector JSONL, resolved graph, topology cluster, and semantic finding.
  Combining them into one generic proposal engine would hide the authority and
  deferral rules that make their artifacts reviewable.

## Follow-up boundary

Serial integration, not this cohort, owns router/catalog/source-inventory and
coverage-matrix promotion. Any later Go or other-language candidate should
repeat the final-artifact, copied-closure, source-hash, partial-coverage, and
native-verification proof before changing those shared declarations.
