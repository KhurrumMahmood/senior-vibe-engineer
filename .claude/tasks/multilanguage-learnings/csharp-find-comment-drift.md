# C# `find-comment-drift` learning packet

## Final value proved

The copied C# lexical/syntax provider and one skill-local consumer reach the
four final comment-drift artifacts for an exact manifest-selected `.cs`
target. The representative result reports four conservative lexical bands:
legacy-term spelling, source-line-shaped reference, section/banner form, and
imperative narration without a frozen rationale lexeme. Every lead retains a
stable ID, Roslyn trivia form and span, comment spelling hash, source hash,
pattern-specific claim description, and the complete provider evidence.

SDK 10.0.302 compiles the exact source/test closure directly with bundled
`csc.dll`, replays the test and executable with exact stdout, and runs the
bundled Roslyn helper offline. The copied closure contains only the selected
`find-comment-drift` skill plus sibling `_csharp`, executes from outside the
checkout, replaces all four artifacts across complete, unsupported, failed,
and recovered states, and preserves every project source byte.

## Honest lexical boundary

This is comment hygiene, not semantic comment drift. Only Roslyn comment
trivia from manifest-selected authored source can create a lead. Quoted,
interpolated, verbatim, and raw strings; directives and disabled text; tests;
generated, vendor, build, tooling, and symlink inputs do not create production
findings. The patterns do not attach prose to declarations or prove prose
staleness, code behavior, control flow, runtime reachability, XML-doc
completeness, or refactor safety.

Complete evidence may be `advisory-findings` or `clean-within-complete`.
Missing .NET is `unsupported/incomplete`; malformed C# or invalid project
evidence is `failed/incomplete`. Neither state can inherit a prior clean or
advisory result. Same-destination tests prove valid-to-failed,
failed-to-unsupported, unsupported-to-valid, project-failed, and final valid
recovery with empty detections whenever evidence is incomplete.

## Roslyn span lesson

Roslyn `TextSpan` positions are zero-based UTF-16 code-unit offsets, not byte
offsets. The fixture puts `café 😀` before the first finding so the test would
fail if UTF-8 bytes or Python code-point indices were substituted. The C#
consumer explicitly renames the inherited provider coordinates to
`roslyn_comment_span` with `unit: utf16-code-unit` and `interval: half-open`.

Structured documentation trivia has another important detail: for a `///`
comment, `SyntaxTrivia.ToFullString()` retains the exterior `///`, while
`SyntaxTrivia.Span` begins after those three exterior characters. The consumer
hashes exactly the source spelling covered by the reported Roslyn span and
normalizes the full trivia text only for lexical pattern matching. It does not
silently widen the span to include documentation exteriors.

## Reuse and publication boundary

The accepted reuse is the integrated language-local `_csharp` provider. The
comment patterns, their natural-language non-claims, output containment, and
four-artifact lifecycle stay inside `find-comment-drift`; no universal comment
AST or cross-language semantic schema was introduced.

This lane intentionally does not edit shared routers, language matrices,
catalogs, plans, or README files. Root integration may register the C# entry
point only after the focused outcome and preserved C# lexical cohort pass.
