# PHP pilot learning packet

Decision: stop after the three frozen pilot outcomes. Keep their correct,
bounded PHP support, but do not expand the other 19 language-level skills or
promote new shared mechanics from P4. The predeclared LOC and copied-closure
gates failed even though aggregate final-outcome latency remained within the
10% comparison limit.

## What generalized

- Strict language profiles, source-role inventory, read-only tool discovery,
  lifecycle transitions, copied-library conformance, and capability projection
  transferred without inventing a shared semantic result schema.
- The final-outcome contract transferred: positive, clean, malformed,
  excluded-role, unavailable/old-tool, valid-to-failed, failed-to-valid, source
  preservation, and native verification are checked at the emitted artifact or
  diff boundary.
- Router handoffs can publish `php-supported`, `php-partial`, and
  `php-unsupported` honestly while keeping task skills in the on-demand library.

## What stayed PHP- or skill-local

- `find-comment-drift` uses `token_get_all(..., TOKEN_PARSE)` for bounded
  lexical comments. It does not claim symbol, Composer, or framework facts.
- `map-subsystem` combines Composer PSR-4 metadata with native PHP validation.
  Its project edges are bounded static imports; dynamic calls, types, container
  wiring, and framework behavior remain outside the result.
- `move-path` supports one string-valued PSR-4 leaf namespace-directory move
  with token-exact namespace and require/include edits. Wider Composer shapes,
  reflection, and dynamic identities remain unsupported.
- Tree-sitter established syntax spans but could not justify a semantic final
  outcome. It was therefore rejected from the production PHP path rather than
  presented as project-resolution support.

## Tool acquisition and setup

- Minimum profile: PHP 8.1 and Composer 2.2.
- The pilot used system PHP 8.4.2 and Composer 2.4.0; project-local executables
  take precedence when present. Composer 2.4 emits deprecation noise on PHP
  8.4, but validation and fixture scripts pass.
- Routed execution installs nothing into the host and requires no network.
  PHP Parser, PHPStan, and Psalm may be used when the host already owns them or
  a future exact on-demand closure explicitly provides them; their facts are
  unavailable otherwise.

## Economics

- PHP adapter-plus-test work was 3,354 lines versus 3,773 for the frozen Java
  equivalent: an 11.11% reduction, below the required 25%.
- The three copied PHP closures total 487,972 bytes versus Java's 385,347:
  26.63% growth, above the allowed 10%.
- Warm medians were 0.999s lexical, 2.481s semantic, and 2.950s mutation.
  Their 6.431s sum is 9.18% above Java's 5.890s sum, within the aggregate 10%
  gate, although lexical and semantic comparisons individually regressed.
- Correct outcomes remain shipped, but the failed LOC and closure gates reject
  broader PHP expansion and new shared abstractions from this pilot.

## Guidance for the C# pilot

- Reuse only the strict profile, source-role inventory, doctor, lifecycle,
  copied-closure harness, terminal cases, and measurement protocol.
- Use Roslyn for syntax, semantic, and rewrite facts. Do not substitute a
  generic parser for project resolution, symbol identity, or safe rewrites.
- Freeze the exact SDK, restore/cache state, solution/project boundary, final
  artifacts, native `dotnet ... --no-restore` checks, and Java/PHP comparison
  paths before implementation.
- Keep Roslyn providers and skill-owned artifact schemas family-local until at
  least two real consumers prove a smaller reusable seam and pass the same LOC,
  closure, latency, and correctness gates.
