# Java J2/J3 expansion learning

J2 and J3 moved Java from the three-skill pilot to fourteen candidate
language-level outcomes: six lexical/filesystem skills, two declared-symbol
skills, and three syntax/report skills joined the original three. All eleven
new outcomes reached their skill-specific final artifacts from self-contained
closures, and the integrated Java suite passed 80/80 before capability
promotion. Promotion and router claims still wait for fresh product review.

The useful split was not “one Java adapter.” Source-role discovery, ordinary
comment text, strict concept text, and folder topology needed only disciplined
first-party `.java` inventory and bounded lexical rules; the locked fixtures
used `javac` as their native oracle. Public declaration inventory, exact body
clones, decision-comment validation, direct-call standards, and method-span
omnibus evidence needed separate family-local JDK compiler-tree helpers. The
helpers share a toolchain, but not a fact schema, failure policy, or final
artifact.

JDK source-file launch is the portable closure mechanism: a copied skill can
run its own `.java` helper with JDK 17 without Maven, Gradle, third-party JARs,
or a repository runtime import. The Java source policy must distinguish
`src/main/java` from tests, test fixtures, integration tests, generated source,
vendor/dependencies, build outputs, and symlinks. Generated markers and names
must be classified before analysis. Java does not imply Kotlin support.

Several language-specific facts should remain local. Java Unicode escapes can
create comment delimiters before lexical tokenization, so decision-comment
auditing validates with the JDK before its ordinary-comment scan. Interface
members can be implicitly public. Exact JDK-tree body fingerprints are clone
evidence only. Parser success does not establish inheritance, annotation
processor/Lombok output, framework behavior, runtime dispatch, or safe reuse.

There is repeated JDK preflight and source-policy code, but extracting a shared
runtime now would make on-demand skills depend on a hidden platform and would
not remove their different output semantics. Reconsider a generated, tested
source-policy template only after a second language cohort proves a net LOC and
maintenance reduction while preserving explicit copied closures.
