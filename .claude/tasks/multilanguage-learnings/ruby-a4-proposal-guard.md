## Bounded outcomes

Five language-local consumers retain separate authority and artifacts:

| Skill | Accepted upstream | Final artifact |
|---|---|---|
| `extract-enum` | one hash-bound `ruby-rbs-implicit-state-v1` candidate plus its A3 fact pack | `targets.json`, `proposal.md` |
| `prevent-regression` | a ready enum target plus a separately hash-bound proposal review | staged exact-field RBS guard, good/bad fixtures, `guard.json`, `verification.json` |
| `propose-boundary` | one human-scouted `confirmed_omnibus` Ruby syntax finding | `inspection.json`, `proposal.md` |
| `propose-folder-reorganization` | one accepted three-sibling Ruby lexical cluster | `inspection.json`, `proposal.md` |
| `unify-shadows` | one hash-bound `ruby-rbs-semantic-duplication-v1` lead plus its A3 fact pack | `proposal.md`, `evidence.json`, `scope.json` |

The shared Ruby-local validator accepts only those producer shapes. It checks
artifact hashes, human reviewer/boundary authority, selected candidate hashes,
and current source hashes. It never launches a detector. Missing, partial,
unaccepted, tampered, or stale evidence writes a fresh refusal artifact and
exits 2. Safe defer, keep-flat/cohesive, and keep-separate remain useful
complete outcomes rather than false proposal failures.

All artifacts preserve the non-claims inherited from their evidence. RBS is
contract authority only; Prism spans and direct spelling are not runtime call
resolution. Ruby dispatch/reflection, reopening/refinements, eval and method
generation, dynamic load paths, Rails callbacks/concerns/ActiveRecord, and
Zeitwerk/autoload remain explicit stop conditions. Human approval remains
separate from both detection and proposal synthesis.

## Copied closure and ML-025 economics

The exact installed union is one helper plus five consumer scripts: 884
physical lines / 40,096 bytes, manifest SHA-256
`12bdf8b04315ad7410a019f72c910f77f8d8f1a9286a0a7b20faee28532772ff`.
Each copied script locates the one sibling `_ruby-semantic` helper outside the
checkout and imports no repository runtime.

- Shared validator `H = 247` physical LOC.
- Five adapters plus focused test `C = 1,043` physical LOC.
- Maintained shared form `C + H = 1,290`; five literal validator copies
  `C + 5H = 2,278`: **43.37% maintenance reduction**.
- Runtime union is 637 adapter LOC. Shared closure is 884 LOC / 40,096 bytes;
  literal per-consumer copies are 1,872 LOC / 81,372 bytes: **52.78% LOC** and
  **50.73% byte** closure reduction.
- Fifteen alternating warm trials launched all five copied adapters through
  `--help`, which imports and resolves the validator but performs no host I/O.
  Shared median was `0.207479s`; literal-sibling-copy median was `0.214720s`:
  **-3.37% latency growth**, below ML-025's 10% ceiling. The adapter/evidence
  work after import is byte-identical in both layouts.

This clears ML-025 without a universal proposal schema, process, cache,
network operation, or cross-language helper. The seam is justified only
because all five immediate consumers enforce the same Ruby acceptance and
source-freshness boundary.

## Transferable learnings and limits

- Acceptance is a separate authority layer: a complete detector result is not
  permission to propose, and a proposal is not permission to install a guard.
- A guard can be narrower than its detector. The staged Ruby guard pins one
  reviewed RBS owner/field/type and deliberately does not masquerade as a
  runtime or Rails enum invariant.
- Source manifests make proposal consumers deterministic and cheap: validate
  cited bytes, then synthesize from accepted facts; do not repeat native
  discovery or detection.
- Keep-separate and safe-defer outcomes need durable artifacts so human
  judgment is retained instead of being mistaken for missing capability.
- The exact-field guard's RBS text check is intentionally bounded. It does not
  validate runtime values, serialization, ActiveRecord persistence, or loader
  identity; those require implementation-time native tests and framework-aware
  review.
