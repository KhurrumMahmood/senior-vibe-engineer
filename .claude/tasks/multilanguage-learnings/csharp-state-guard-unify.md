# C# accepted state/guard/unify learning

- Keep detection and accepted outcomes separate: the three consumers only
  validate and project integrated Roslyn facts plus final producer artifacts.
- C# acceptance must bind the exact artifact, candidate set, source/fact hashes,
  selected symbol or pair, reviewer notes, and a closed boundary-verdict map.
- A state proposal is still read-only after review. Guard authority is a second,
  migrated-tree acceptance with fresh facts and an exact disposable reversion.
- A useful type guard proves both directions: the accepted migrated tree compiles
  with it, while a buildable String reversion passes native checks without it and
  fails compilation with it.
- Duplication disposition needs exact resolved caller sets for both methods and
  an explicit reviewer verdict that static body/contract shape is not runtime or
  behavioral equivalence.
- Replace output directories as terminal bundles so success, refusal, and
  recovery cannot leave contradictory stale artifacts behind.
