# Kotlin/JVM `find-comment-drift` learning packet

## Final value proved

The copied Kotlin lexical provider and one thin consumer reach the four final
comment-drift artifacts for an exact manifest-selected `.kt` target. The
representative advisory result reports stale terminology, brittle source-line
references, detached section banners, and narration comments with exact
comment forms, spans, source hashes, and stable finding IDs. A clean target
produces `clean-within-complete` rather than relying on an empty intermediate
scan.

Kotlin/JVM 2.4.10 diagnostics for JVM 17 gate the authored source manifest.
The existing native evidence replays the exact test and smoke commands and
outputs. The copied closure contains only `find-comment-drift` plus sibling
`_kotlin`, runs outside the checkout, replaces artifacts across stale,
malformed, missing-tool, and recovered states, and preserves every selected
source byte.

## Honest boundary

This is lexical comment hygiene, not semantic comment drift. It does not
associate a comment with a declaration or infer that the described behavior
is stale. Strings and tests, generated, vendor, build, tooling, symlink,
unreadable, Java, and `.kts` inputs do not create findings. Annotations,
compiler plugins, Gradle variants, reflection, framework behavior, and runtime
correctness remain outside the claim.

The closure remains external-library-only because the consumer needs the
copied `_kotlin` provider and current host-native evidence. Missing or stale
evidence yields an incomplete terminal artifact with no clean claim; it never
silently falls back to grep or promotes an empty finding set.
