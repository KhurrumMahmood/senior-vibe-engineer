# Java `propose-boundary` learning packet

Java v1 proposes a read-only boundary for one named package only after the JDK
compiler parses and attributes every eligible source. It groups top-level types
by leading name domain, reports public types as candidate compatibility
surfaces, and records direct imports and fully-qualified caller references only
when compiler resolution confirms their identity. A cohesive one-domain target
defers rather than manufacturing a split.

The copied skill uses JDK 17 source-file mode and no Maven, Gradle, language
server, annotation processor, or third-party JAR. The fixture proves positive,
cohesive, malformed, excluded, old-JDK, symlink, source-immutability, and copied
closure outcomes through final Markdown and JSON artifacts.

The important transfer is the evidence shape, not the implementation: native
tool preflight, explicit incomplete statuses, final artifacts, source
fingerprints, and cutoff-tie visibility all carried over. Java package/type
attribution did not transfer from Go or TypeScript, and Java does not imply
Kotlin or framework support.

The standalone runner is 677 lines after closeout regressions. That is tolerable for this pilot but should
not become a copy-paste pattern across every skill. The proposal and mutation
families now prove a second need for JDK launch/path/JSON plumbing, but their
semantic outputs differ. Keep the analyzers family-local for now; separately
measure whether a small launcher utility can remove plumbing without creating a
shared Java fact platform or weakening copied/on-demand execution.
