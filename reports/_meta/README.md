# reports/_meta — skill effectiveness log

`reports/*` is gitignored; the `!reports/_meta/` rule in `.gitignore`
keeps this directory tracked. `reports/sites-maintainability/` is the
other intentional exception (round-level audit trails). Everything else
under `reports/` is per-scan, machine-local output that should not ship
in commits.

## Why track these files

- `effectiveness.jsonl` — append-only, one line per skill run. Each line
  records `{skill, scan_id, ts, findings_total, buckets, notes, target}`.
  This is the cross-time signal that tells us whether the maintenance
  skills (the full `/find-*`, `/extract-*`, `/triage-debt`,
  `/refactor-subsystem`, `/fix-workflow`, `/unify-shadows`, etc. catalog
  in `.claude/docs/skill-catalog.md`) are producing fewer findings over
  time in the same code areas.
- `dashboard.md` — aggregated view generated by
  `scripts/skill_effectiveness.py` from the jsonl. **Regenerate after
  appending runs** — the file is otherwise stale. Safe to commit the
  current snapshot alongside the jsonl entry that produced it.

The working backlog index across all skill outputs lives at
`reports/BACKLOG.md` (gitignored — local working file, not committed);
per-scan `reports/<skill>/scan-*/` directories are also gitignored and
should not be cited from here.

## What should NOT end up here

- Per-scan report directories (`reports/dormant/scan-*`,
  `reports/duplication/scan-*`, etc.). Those stay gitignored.
- Scratch notes, raw scout output, or sub-agent scratch files.
- Anything tied to a single machine or a single in-flight review pass.

## Updating

Skills append to `effectiveness.jsonl` automatically at the end of
a run. If you hand-edit the file, keep it as valid JSONL (one object
per line, newline-terminated) so `scripts/skill_effectiveness.py`
can still parse it. Run the script with no args to refresh
`dashboard.md`.
